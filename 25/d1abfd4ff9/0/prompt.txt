<title>Hosted Custos MCP: agent-as-child-identity + credential-forwarding sidecar</title>
<description>
Stub issue to spawn implementation plans from the design plan `docs/design-plans/2026-07-14-hosted-custos-mcp.md`.

**Design verdict:** attribution and hosting are **independent choices**. Self-hosted "agent acts directly as me" (the shipped stdio MCP) stays first-class; for the *hosted* tier the agent becomes its **own sovereign identity** (own handle, recovery key held in the user's Obsign wallet) served by a tier that **forwards** the caller's credential rather than holding it. The only off-limits combination is hosted + acts-as-you + durable custody.

**The two attribution models (both supported):**

* **Acts as you (delegate)** — writes into your repo, actions carry your identity. Correct/safe for **self-hosting** (you hold your own credential); this is what `tools/mcp/` ships today and must keep working.
* **Acts as itself (sovereign child)** — own DID/repo/handle, recovery key in the wallet, day-to-day signing delegated + revocable. The **hosted default** — even a durable bot credential can't act as you.

**Scope (from the design plan):**

* Preserve + document the **self-hosted acts-as-you** path (stdio today; a self-hosted HTTP sidecar later). First-class, not a fallback.
* **Sovereign child identity** for the hosted path — own DID/repo/handle, recovery key in the wallet (reuses existing `did:plc` genesis/rotation machinery), delegated revocable signing.
* **Credential-forwarding** hosted tier — MCP remote auth = OAuth against Custos (the existing AS); the caller's token rides each request; nothing durable is cached. Applies whether the tier is a Node sidecar or folded into axum.
* **Sidecar first** — reuse the `tools/mcp/` tool surface, swap stdio → Streamable HTTP, singleton `AgentSession` → per-caller map, deploy as a third Railway service (`mcp.obsign.org`) over private networking. In-PDS consolidation is a possible later step, not step one.
* **Handles:** flat subdomain now (`alice-writer.obsign.org`); nested (`writer.alice.obsign.org`) needs on-demand TLS — phase two; custom domains later via native ATProto handle verification.
* **Deployment tiers:** co-located hosted (default, Railway private net) · self-host acts-as-you (stdio/sidecar) · host-your-own sidecar connected over **Iroh** (later).
* **Gating:** an agent identity can only be minted as a child of an account on this PDS (entitlement falls out of the ownership graph).

**Two ADRs to write alongside implementation** (next free numbers **0023 and 0024** — 0022 is now taken by `0022-did-web-for-user-owned-domains.md`):

* ADR-A (0023) — Agents *may* be sovereign child identities (the hosted default); the acts-as-you delegate model stays first-class and is the self-host default. Records the attribution × hosting matrix, not a replacement.
* ADR-B (0024) — The hosted agent tier forwards credentials; never holds durable user/agent secrets (security posture).

**Explicitly deferred (do not couple to this work):** [honker.dev](<http://honker.dev>) (async agent job queue / audit-event outbox — reach for it when agents get scheduled/async behavior) and Litestream read replicas (whole-PDS geo-scaling lever; read-after-write footgun for write-heavy agents).

**First implementation slice:** agent-as-child-identity minting + a credential-forwarding Streamable-HTTP sidecar for one tool (`create_post`) against staging, with ADR-0023 and ADR-0024 written alongside — without regressing the existing self-hosted acts-as-you stdio path. Break the design plan into the design → test-requirements → phases triad per `docs/archive/README.md`.

Relates to ADR-0019 (auth.md agent auth), ADR-0001/0004 (client-held rotation key), the sovereign-session work (<issue id="814e9039-1031-4e90-9e40-cc74b1cc2c0e" href="https://linear.app/malpercio/issue/MM-306/sovereign-passwordless-login-mint-a-custos-session-from-a-device-key">MM-306</issue> / <issue id="25aa82ae-c063-4c30-afb1-bd8d65182211" href="https://linear.app/malpercio/issue/MM-351/custos-post-v1sessionssovereign-with-current-plc-rotation-key">MM-351</issue> — the delegation primitive this mirrors), managed-identity-hosted-on-Custos (<issue id="dffcbf51-33df-4fc6-88aa-41a1c6868bd1" href="https://linear.app/malpercio/issue/MM-279/managed-didweb-hosting-optionally-serve-didjson-for-user-owned-domains">MM-279</issue> / <issue id="2a4f70a2-a430-4ce8-a6f5-ecc2218d474f" href="https://linear.app/malpercio/issue/MM-285/wallet-didweb-ceremony-the-22-newexisting-did-selfcustos-hosted-with">MM-285</issue>), and the iroh-tunnel exploration (`docs/design-plans/2026-07-11-iroh-http-tunnel-exploration.md`).
