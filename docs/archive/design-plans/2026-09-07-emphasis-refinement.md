# Clear Signal: final Emphasis refinement

> Historical design evidence. Follow the [selected Emphasis handoff](../../design-plans/2026-09-07-clear-signal-emphasis.md) for implementation. Earlier recommendations and prototype limits below describe their original review round.

Date: 2026-09-07

Status: historical exploration; replaced by the selected Emphasis handoff


The user selected Emphasis from the [Split Panel refinements](2026-09-07-split-panel-refinements.md) and requested a final polish pass. The chosen visual identity stays intact: a strong colored conclusion, a quieter adjoining evidence area, and explicit next actions. This is a prototype refinement, not an implementation in the production apps or websites.

## Changes

- On phones, the status icon sits beside the heading rather than occupying a separate line. Routine heading size and padding are reduced without removing explanatory copy.
- Routine evidence uses two labeled columns, borrowing Ledger's compact arrangement. Warnings retain full-width deadline rows immediately above the review action.
- Phone header, identity spacing and navigation groups are slightly tighter. Full-width task rows retain at least 54-pixel height in the prototype; primary buttons retain at least 48 pixels.
- Brass Console puts the issuing server and biometric confirmation immediately above Generate claim code. The blue conclusion pane retains the terse operator heading and explanation.
- Marketing uses a bounded hero width, balanced spacing and the compact evidence arrangement. Documentation retains its reading column and joined instruction/evidence panel.
- Narrow consent pages stack requester metadata labels above their values, giving complete domains room to wrap. Expired requests hide the permission-review sections and retain the requester context and neutral restart guidance.
- The prototype now focuses on the selected design. A before/after wallet view compares the previous Emphasis composition with this refinement using the same content. Dark/light and 390/320-pixel previews remain available.

## Preserved constraints

Both apps and all previously modeled web surfaces remain in the comparison. Operator pages keep their dark technical register; Obsign retains its humane voice and both appearances. The palette and its recorded contrast pairs are unchanged. The selected appearance does not alter status meaning.

Review still precedes signing. The deadline carries into the change-review specimen. Unavailable observations never become verified through a visual retry, and a failed code request never yields a newly issued code. Expired consent does not claim that access was never previously granted. All sample identities, hosts and times are synthetic; prototype actions remain local.

## Validation scope

Rendered the dark/light wallet, before/after comparison, a 320-pixel warning and its transition to change review, both apps, desktop marketing, and compact expired consent. Checked browser errors. These are visual-prototype checks; native Dynamic Type, VoiceOver and the full accessibility audit belong to implementation validation.

The next phase can implement this chosen direction against the actual route inventory and existing component/token systems. The preceding proposal documents retain the ecosystem coverage and migration constraints; this note records only the final visual refinements.
