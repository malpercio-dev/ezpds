# Custos v2, rebuilt in place

**Status: adopted 2026-09-06 (Wave 11, umbrella MM-557).** The four decisions in §8 were taken that day. Live per-issue status is Linear's (`linear_wave_status`, team `MM`, `label_prefix: "Wave"`), not this document's.

What we would do differently if we started over, delivered as a sequence of ordinary releases that never break a client, a database, or a phone that already holds keys.

- **Scope:** the PDS crate (Custos), the two Tauri iOS apps (Obsign wallet, Brass Console), the shared crates, and the Node tooling around them.
- **Constraint:** every step ships as a normal PR behind the [frozen contracts](../architecture/frozen-contracts.md). No flag day, no parallel v2 branch, no new app record.
- **Revises:** [ADR-0013](../architecture/decisions/0013-native-swiftui-shell-over-rust-core.md) (split into "bound core" and "native shell"; §4.1). Extends [ADR-0005](../architecture/decisions/0005-functional-core-imperative-shell.md) (FCIS). [ADR-0038](../architecture/decisions/0038-hand-written-xrpc-methods-over-lexicon-codegen.md) narrows §3.1.
- **Origin:** a proposal written 2026-09-05 against the workspace at 0.16.2 (commit 86bdbe56). Line counts are raw `wc -l` over `.rs`, `.svelte`, and `.ts`; coupling counts are grep over `tauri::` tokens.

## 0. Summary

The codebase is not wrong; it is a v1 that grew to 148k lines of server Rust and 48k of wallet Rust by copying the nearest sibling and adding a shell-script guard when the copy drifted. The 2026-09-05 quality audit named the pattern: rules that live in a `scripts/*-check.sh` hold, rules that live in prose drift. A v2 takes the next step: rules that live in a *type* cannot drift at all.

Five things change, all in place:

1. **One PDS client, not four.** The wallet, the operator console, the MCP server, and the interop CLI each speak XRPC + DPoP to Custos with their own code. A `custos-client` crate becomes the single implementation, with the TypeScript tools consuming generated types.
2. **The wallet's Rust becomes a platform-free core.** Most of it already has no Tauri coupling in its logic; the coupling is 112 one-line command wrappers, dependency injection through `tauri::State`, and four `emit` calls. UniFFI turns that core into a Swift package and a Kotlin AAR. The native-shell decision stays separate and trigger-gated; ADR-0013's trigger needs rewriting because the repo already reaches `BGTaskScheduler` from Rust.
3. **Guards become types.** The auth seam, the SSRF client, the space-auth seam, and the DPoP binding are enforced today by grep. In v2 the forbidden call is private and the safe one is the only public path.
4. **Every ceremony is one journaled state machine.** Migration, recovery, rekey, agent-child minting, and device transfer each hand-roll resumability. One `Journal` helper serves server and wallet.
5. **The server crate splits along seams that already exist.** The capability table already models features as gated entries; Spaces already registers conditionally. Feature crates make that structure real and cut compile and test time.

Three things explicitly stay: SQLite with Litestream, the Functional Core / Imperative Shell split, and the browser harness plus client-side conformance suites as the primary test oracle.

## 2. The frozen contracts

"Backwards compatible, in place" means the contracts do not change. Everything in §3 and §4 is judged against them, and the existing suites are the oracle: `http_suite.rs`, the OAuth conformance suite, the MCP conformance suite, the harness scenarios, and the docs screenshots.

The contract list, with the suite that proves each row, is the living doc [`docs/architecture/frozen-contracts.md`](../architecture/frozen-contracts.md). It is the acceptance oracle for every Wave 11 issue; cite a row by its heading.

The device row is the hard one. A Secure Enclave key is bound to the app's access group, not to the UI framework in front of it. A SwiftUI build shipped as an update to the same app record reads the same items as the Tauri build, provided the core keeps every account-name constant. That is the whole reason a native shell can be an in-place release rather than a migration.

## 3. Custos: what changes

Each item names the evidence in the repo, the v2 shape, and how it lands without a flag day.

### 3.1 One client crate

- **Evidence:** four implementations of "call Custos with a DPoP-bound token and handle the nonce challenge." The wallet's copy is spread over `pds_client`, `oauth_client`, `http`, and `oauth`; the console's is `relay_client`.
- **v2 shape:** `crates/custos-client`: typed XRPC methods, DPoP with ADR-0032's reusable nonces, service auth, the sovereign-session and auth.md flows, and one `UserFacingError` mapping (ADR-0031). TypeScript tools get generated types from the same lexicons; later, a napi or wasm build of the crate itself. The typed methods are hand-written, not generated; ADR-0038 records why and when to revisit. The console does not share DPoP at all (ADR-0018 signed envelopes), so the crate serves the wallet and the future core, not cross-app dedup.
- **In place:** a pure client-side move. The wallet and console swap one module at a time; the conformance suites keep their own wire client deliberately, since a shared client would hide the very regressions they exist to catch.

### 3.2 Shared identifier types

- **Evidence:** DID and handle validation lives in `crates/pds/src/identity/`. The wallet does not depend on `pds`, so it cannot reuse them; every string crossing the IPC or the wire is a `String`.
- **v2 shape:** `common` grows `Did`, `Handle`, `Nsid`, `Rkey`, `AtUri`, `Cid` with parse-once constructors and serde. Server, wallet, console, and the client crate share one parser. Property tests move with them.
- **In place:** introduce the types, then convert function signatures inward from the extractors. No wire change: the JSON is the same string.

### 3.3 Guards become types

- **Evidence:** `auth-seam-check`, `space-auth-seam-check`, and `ssrf-client-check` grep for a forbidden call. They work, but they encode a rule the compiler could hold.
- **v2 shape:** `verify_access_token` becomes private to `auth::extractors`; a route can only obtain an `Authenticated` value through the DPoP-binding extractor. Outbound caller-influenced URLs become a `CallerUrl` newtype that only `HardenedClient` accepts; the plain `reqwest::Client` has no method taking one. Three scripts retire. Docs-parity guards (runbook, capabilities, Bruno) stay as scripts, since they compare against prose.
- **In place:** add the type, migrate call sites, delete the script in the same PR so the gate never goes unguarded.

### 3.4 One sweep scheduler

- **Evidence:** the module map lists ten periodic sweeps and labels three of them "template: `<sibling>.rs`", the copy pattern the conventions forbid. Each carries its own interval loop, its own `sweep_status` reporting, and its own retention-above-replay assertion.
- **v2 shape:** a `Sweep` trait (name, cadence, one `run(&pool)`) and one scheduler that owns the loop, jitter, the last-run record for `/v1/admin/health`, and the boot-time first pass. A sweep is then thirty lines of SQL.
- **In place:** wrap the existing sweeps one by one; the health JSON is unchanged.

### 3.5 Feature crates along existing seams

- **Evidence:** one 148k-line crate means every test run and clippy pass compiles OAuth, Spaces, agents, blobs, notifications, and admin together. Yet `capabilities.rs` already lists features as gated entries, and Spaces already registers only when enabled.
- **v2 shape:** `custos-db` keeps the pool and the single linear migration log (one database, one history). Feature crates such as `custos-oauth`, `custos-spaces`, `custos-agents`, `custos-blobs`, `custos-firehose` each export a `Router` slice, their query modules, and their capability entry. The `pds` binary composes them.
- **In place:** extract the most self-contained feature first (Spaces, because its gate already exists), keep route paths identical, and let `bruno-check` prove nothing moved. Migrations never leave `custos-db`, so V-numbering stays linear by construction.

### 3.6 Ceremonies as journaled state machines

- **Evidence:** `agent_child_core.rs` is "resumable rather than atomic, because the plc.directory publish can't join a SQLite transaction." The wallet's `migration_orchestrator.rs` is 5k lines for the same reason; `share_recovery`, `rekey`, `transfer` each carry their own step bookkeeping.
- **v2 shape:** one `Journal` helper: a typed step enum, a persisted cursor, idempotent step functions, and a resume entry point. The server keeps it in SQLite, the wallet in the Keychain-backed identity store.
- **In place:** start with the newest ceremony (agent-child minting), then port the wallet migration, the one with the most recorded defects. Existing in-flight records get a one-time adapter.

### 3.7 No panics outside tests

- **Evidence:** the audit counted 83 production panic sites across the workspace after excluding inline test modules.
- **v2 shape:** `#![deny(clippy::unwrap_used, clippy::expect_used)]` at every crate root, with an `expect` allowed only under a comment stating the invariant. The imperative shell converts errors through the ADR-0031 seam.
- **In place:** enable per crate, smallest first. The cheapest item on the list.

### 3.8 Leave the patched MST

- **Evidence:** the repo's core data structure comes from atrium-repo 0.1.8, vendored with a patch for a data-loss bug that ate 64 records twice (ADR-0034). The upstream issue, atrium-rs/atrium#343, has had no maintainer response. A gate test exists so the patch cannot silently drop. MM-521 scopes the exit: 65 `atrium_repo::` references across 16 files, with the SQLite block store implementing atrium-repo's block-store traits and the sync surface (streaming `getRepo`, `getBlocks`, record proofs, firehose block sets) built on its API.

| Exit | Cost | What you end up carrying |
|---|---|---|
| Upstream the patch, track atrium-repo | Days | A 0.1.x crate with thin MST tests and an unresponsive maintainer. Cheapest and weakest. |
| Migrate to atproto-repo (MM-521) | Weeks: storage-seam swap, a block-store adapter, export path re-proved streaming | A maintained crate with roughly 40 MST unit tests and a precedent migration (kan-tools/kan#9, validated at 25k insert/get cycles and 2.5k CAR round-trips). Known caveat: its CAR writer has no incremental append, likely moot since blocks live in SQLite. |
| Own the MST in `repo-engine` | Weeks, then permanent | Full control and property tests against the reference vectors, at the price of being sole maintainer of the structure that holds every user's data. |

- **v2 shape:** MM-521 is the default. It removes the fork, buys real test coverage, and its acceptance shape is already engine-agnostic. Owning the MST is the fallback only if the design plan finds atproto-repo's storage model cannot sit over the SQLite block store or cannot keep `getRepo` streaming. Upstreaming alone is not an exit.
- **In place:** all three keep commits, MST node encoding, and CAR shape byte-identical; `mst_split_gate.rs`, a kan-style stress harness, the interop fixtures, and a live `getRepo` and firehose read against a relay are the oracle. ADR-0034 gets a Superseded-by.

## 4. Mobile: the Rust core

The question was whether to extract a reusable Rust core with foreign bindings into native iOS and Android apps. The answer is yes to the core, now, under the existing Tauri app; and a separate, later yes-or-no to each native shell. ADR-0013 fuses the two decisions and should be split.

### 4.1 How much is already a core

The wallet's Rust is closer to a library than its file layout suggests. Coupling to Tauri appears in three forms, and none of them is in the logic:

| Coupling | Count | What replaces it in a core |
|---|---|---|
| `#[tauri::command]` wrappers | 112 | Nothing; the wrapper becomes a one-line delegate to a core method, generated by a macro so the command table and the core API cannot diverge. |
| `tauri::State<T>` injection | 84 | A `Core` struct holding the same singletons, constructed once by whichever shell is running. |
| `AppHandle` for spawn and events | 22 refs, 4 `emit` | An `EventSink` trait the shell implements; the Tauri impl calls `emit`, the Swift impl posts to a Combine publisher. |
| Apple APIs through `objc2` | 3 modules | Already Rust: `bg_backup` (BGTaskScheduler), `apns`, `blob_backup` (iCloud). They stay in the iOS platform crate or move to Swift; either works. |
| Keychain and Secure Enclave | 2 modules + 1 crate | Already behind a trait: `ios-device-key`'s `KeychainStore` is exactly the seam a core needs. The wallet's `keychain.rs` and the console's copy fold into it. |

Two other artefacts are core interfaces written in the wrong language. The 27 files under `src/lib/ipc/` define a typed command contract with `{ code: "SCREAMING_SNAKE" }` errors; that is the UniFFI interface, transcribed in TypeScript. And the harness fake is a hand-written second implementation of the core's behaviour, which a wasm build of the real core would replace.

**ADR-0013's trigger has already been falsified.** The ADR says background PLC monitoring "needs Apple's BGTaskScheduler, reachable only from native Swift." `bg_backup.rs` schedules a `BGProcessingTask` from Rust through `objc2-background-tasks` today. So `plc_monitor`'s foreground interval can move onto that bridge without leaving Tauri, and the one signal the ADR named as justifying a native shell can never fire. The native-shell decision needs a real trigger: Android demand, a WKWebView defect that blocks this app, or a product call that the wallet's assurance story requires native fidelity.

### 4.2 The layering

```
Shells (dashed)   Tauri + Svelte (today)  | SwiftUI (when triggered) | Kotlin/Compose (if Android) | Browser harness (wasm)
                  112 delegate commands   | UniFFI Swift package     | UniFFI AAR via cargo-ndk    | in-memory keystore
-------------------------------------------------------------------------------------------------------------------
obsign-platform-ios   Keychain + Secure Enclave KeychainStore, BGTaskScheduler bridge, APNs token, iCloud container.
                      The only crate that links Security.framework.
obsign-core           Platform-free. Identity store, claim, migration, recovery and share ceremonies, rekey, handle
                      change, PLC monitor check_all, notification registration, app passwords. Talks to the platform
                      through five traits: KeyStore, Signer, EventSink, Scheduler, Clock.
custos-client         Typed XRPC, DPoP, service auth, sovereign session, auth.md. (Brass Console does not use it.)
crypto · repo-engine · common   P-256, did:key, HPKE, Shamir, did:plc ops, MST/CAR, identifier newtypes. Unchanged.
```

The rule that makes the diagram true: `obsign-core` has no `cfg(target_os)` and no Apple crate in its dependency list. A wasm build in CI is the cheapest way to prove that and keep it proved.

### 4.3 Binding technology

| Option | Targets | Verdict |
|---|---|---|
| UniFFI, proc-macro mode | Swift, Kotlin, Python; async supported | **Recommended.** Used by Firefox, matrix-rust-sdk, Bitwarden. Generates both shells from the same annotations; no IDL file to keep in sync. |
| swift-bridge | Swift only | Better Swift ergonomics, no Android path. Reconsider only if Android is ruled out permanently. |
| flutter_rust_bridge | Dart | Only if the shell becomes Flutter, which ADR-0013 reserves for the Android case. Not recommended: Flutter's UI fidelity is the wrong fit for the wallet's brief. |
| Hand FFI over cbindgen | Anything | Every type marshalled by hand. No. |

Packaging: an XCFramework wrapped in a Swift package built by `just ios-core`, and an AAR built by `cargo-ndk`. The XcodeGen template already builds a second target (the Notification Service Extension), so the Swift package slots in next to it.

### 4.4 What Android changes in the core's design

Android queries have come in, and the 2026-09-06 decision was to design the traits for it now. Each row is a platform trait method, not a core change, except the cloud share slot.

| iOS today | Android equivalent | Core implication |
|---|---|---|
| Secure Enclave P-256 | Android Keystore, StrongBox where present | Same did:key; `Signer` reports whether the key is hardware-bound so the UI can say so honestly. |
| iCloud Keychain for share 1 | No equivalent sync store | `KeyStore` exposes the synchronizable slot as optional; the share ceremony must handle "no cloud slot" by routing share 1 to the user or to a second escrow. The one real design change. |
| APNs via the notify relay | FCM | The relay is APNs-only today; it would grow a second transport. The HPKE sealing is transport-agnostic already. |
| ASWebAuthenticationSession (ADR-0006) | Custom Tabs | Shell concern, not core. |
| BGTaskScheduler | WorkManager | `Scheduler` trait; the core schedules "check identities" and does not know how. |
| Notification Service Extension | FCM data message handled in-process | The unseal function is in `crypto`; Android calls it directly with no extension bundle. |

### 4.5 The Brass Console rides along

The console's Rust is 5.5k lines of which 5k is Tauri-free. It authenticates with ADR-0018 device-signed envelopes, not DPoP, so it shares `ios-device-key` with the wallet but has no use for `custos-client`; a native console, if ever wanted, is a thin shell over its own small relay client. Keep it on Tauri as long as the wallet is.

## 5. What we keep, on purpose

Naming these prevents a v2 from re-litigating settled decisions.

| Decision | Why it stays |
|---|---|
| SQLite, single-connection WAL pool, Litestream | The write path is serialized by design, the firehose relies on it, and the master-key and disaster runbooks are written for one file. A Postgres port would be a second product; the milestone map's "PostgreSQL option" is dropped. |
| Functional Core / Imperative Shell (ADR-0005) | The reason the wallet core extraction is cheap. v2 extends it: the wallet gets its own named shell boundary instead of the Tauri crate being the shell by default. |
| Hand-rolled APNs and SigV4 clients | Evaluated and rejected replacements in 2026-07 (second HTTP stack, duplicate rustls major). Small, tested, and they do not drift. |
| Conformance suites written from the client's side of the wire | Five OAuth bugs shipped past a green Rust suite. New surfaces get their conformance suite before their unit tests, not after. |
| Browser harness as the agent's UI driver | How every screen is reached without a simulator and how the docs screenshots stay honest. A wasm core makes it stronger, not obsolete. |
| OTel-native observability (ADR-0028), Railway native deploys (ADR-0009), OCI not Nix (ADR-0008) | Working, documented, no pressure. |
| Script guards for docs parity | Prose cannot be typed. Runbook parity, capability docs, Bruno coverage, plan status stay as scripts. |

## 6. Sequencing

Two tracks, both strangler-style. A phase is done when its gate is green and the frozen-contract suites are unchanged. Server and mobile tracks are independent until M3 needs `custos-client`.

| Phase | Work | Gate |
|---|---|---|
| **S0 · M0** Freeze and instrument | Write the frozen-contract list into `docs/architecture/` as a living doc. Add the one missing oracle: a test that pins every wallet Keychain account-name constant, so a core extraction that renames one fails in CI rather than on a phone. | New test in `ios-device-key` and the wallet; no behaviour change. |
| **S1** Types and client | `common` newtypes (MM-552), then `custos-client` (MM-556 grown to the full client). Wallet and console adopt it module by module. | Both apps' Rust unit tests on the macOS host target; OAuth conformance unchanged. |
| **S2** Guards to types, panics denied, sweeps unified | Three seam scripts retire in the PRs that add their types. `unwrap_used` denied crate by crate. The `Sweep` trait absorbs the ten loops. | `just ci-pds`; the health endpoint JSON diffed against a fixture. |
| **S3** Feature crates | Spaces first, then OAuth, agents, blobs, firehose. Migrations stay in `custos-db`. | `bruno-check` proves the route table is identical; `http_suite` green per extraction. |
| **S4** Journal helper; MST exit | Port agent-child minting, then the wallet migration orchestrator, onto `Journal`. Run MM-521's design plan and execute the atproto-repo migration, falling back to owning the MST only on the conditions in §3.8. | Live migration round trip against staging, as in the 2026-07-12 closure; `mst_split_gate` plus the stress harness; a live `getRepo` and firehose read against a relay. |
| **M1** Extract `obsign-core` under Tauri | Move the Tauri-free modules first, then replace `State` injection with a `Core` struct and `AppHandle` with `EventSink`. Commands become generated delegates. Move `plc_monitor` onto the existing BGTaskScheduler bridge; revise ADR-0013's trigger. | Wallet host tests; all harness scenarios; a TestFlight build installed over the previous one still lists every identity. |
| **M2** Prove the core is platform-free | Build `obsign-core` for wasm in CI with the in-memory `KeyStore`. Replace the harness fake's behaviour with the real core where cheaper; keep the fake's scenario scripting. | A wasm target in `ci.yml`; the docs-screenshot pipeline unchanged. |
| **M3** Bindings without a shell | UniFFI annotations, a Swift package target in the XcodeGen template, and one Swift logic test that drives a claim flow against the hermetic PDS through the bindings. No UI yet; this proves the packaging. | The iOS PR lane builds the package; the Swift test passes. |
| **M4** Native shell, only on a trigger | If a trigger from §4.1 fires: SwiftUI over the package, shipped to the same app record, first to internal TestFlight installed over the Tauri build. The install-over is the compatibility test. Android follows the same M3 packaging with a Kotlin shell if that trigger fires. | Every identity, session, backup, and share slot readable after install-over; NSE still unseals. |

### Risks worth naming

- **Extraction churn on a live app.** M1 touches every wallet module. Do it in the order the modules are already Tauri-free, and never in the same release as a ceremony change.
- **Feature-crate cycles.** Routes that import a sibling route today (the isolation rule forbids it, and it mostly holds) will surface as compile errors at S3. That is the point, but budget for it.
- **The MST engine swap is the one item that can lose data.** Hence the oracle that already caught the last loss, plus the stress harness MM-521 calls for.
- **Two shells in one repo.** M4 means Tauri and SwiftUI coexist for at least one release. The XcodeGen template and `ios-template-check` are built for exactly this.
- **Stacked PRs get no CI above the bottom one.** The PDS gate and iOS compile lanes trigger only on PRs to `main`, so a stack has one compiled PR until a local build of the stack top is run by hand. Any later stack needs that build as part of review.

## 7. What we would not do

- **No PostgreSQL.** Remove it from the milestone map rather than carry a hedge.
- **No Swift reimplementation of anything in `crypto`.** ADR-0013 already rules this out; it stays ruled out.
- **No new app record, bundle id, access group, or container.** ADR-0030 says why.
- **No big-bang rename.** `ezpds` to Custos in crate names, and the "relay" collision with the AT Protocol term, are worth fixing, but one crate at a time inside the S3 extractions where the crate is already being renamed.
- **No lexicon-generated route handlers.** Tempting with 148 handler files, but the handlers are where the reference-parity error messages live. ADR-0038 extends this to the client crate's typed methods; generate the TypeScript types for the Node tools only.
- **No second repo.** The core crates stay in the workspace; the iOS paths filter and `ios-paths-check` already keep pure-PDS changes off the macOS lanes.

## 8. Decisions taken

All four were taken on 2026-09-06.

1. **Split ADR-0013 into two.** One ADR for "the wallet's Rust is a bound core" (Accepted), one for "a native shell" (Deferred, with the rewritten trigger).
2. **MST: MM-521 is the exit, owning is the fallback.** The atproto-repo migration over both upstreaming and owning; the design plan MM-521 asks for proves the block-store adapter and streaming export.
3. **Postgres off the map.**
4. **Design the traits for Android now.** Queries had already come in. The optional cloud slot in the share ceremony and the platform delta plan follow from it.
