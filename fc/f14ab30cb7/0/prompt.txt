## The fields

| Endpoint | Fields | What they mean |
| -- | -- | -- |
| `GET /v1/admin/health` | `storage.blobUnownedCount`, `storage.blobUnownedBytes` | Stored blobs no account claims. Expect ~0 — GC drops a physical row with its last owner, so a row is unowned only between two statements. A standing value means bytes intact, ownership gone. |
| `GET /v1/accounts/:id/storage` | `uploadedBlobCount`, `uploadedBlobBytes` | Physical rows naming this account as uploader, beside the ownership figures. |
| `GET /v1/admin/accounts` | `didWebHosting` | Whether Custos serves this account's did:web document. |

## Suggested scope

1. **Status screen** — surface `blobUnownedCount`/`Bytes` in the storage block. This one is genuinely alertable: it needs no threshold tuning (~0 is the real baseline), and unlike a stale `blobGc.completedAt` it fires while the sweep is still running on schedule — the exact condition that made the original loss invisible for six hours. Worth a distinct treatment from the ordinary blob counts, not another neutral row.
2. **Account detail / storage** — show the uploaded figures beside the owned ones. Divergence here is **not** a fault by itself: blobs are content-addressed and shared, so owned-not-uploaded and uploaded-not-owned both occur normally. Present it as a second reading, not a warning — a red badge on benign sharing would train the operator to ignore it.
3. **Account list/detail** — a `didWebHosting` indicator. The flag gates a serve path that 404s indistinguishably from an unknown host when off, so its value is telling "not hosted" apart from "broken".

## Constraints

* Brass Console brief: `apps/admin-companion/PRODUCT.md` + `DESIGN.md` (terminal-native, cool-slate/gold, monospace-forward — **not** the Obsign register). Target `/impeccable` at `apps/admin-companion` so it loads the right brief.
* Status never by colour alone (WCAG 2.2 AAA): pair any integrity state with text + icon + position, the way the sweep rows already name `failed <n>` versus `stale`.
* Older relays predating these fields must degrade to "not reported" rather than failing the screen — the same posture #439 took for the sweep `errors` field.
