Files that changed (read them for specifics):
- `apps/identity-wallet/scripts/ios-postinit.sh` — now applies FIVE patches. The docs only mention three. The two undocumented ones:
  - Patch D: appends `CODE_SIGN_ALLOW_ENTITLEMENTS_MODIFICATION = YES` after each `CODE_SIGN_ENTITLEMENTS` line (tolerates Xcode's spurious "entitlements modified during build" failure). This one already existed but was never documented.
  - Patch E (new): injects `OTHER_LDFLAGS = "$(inherited) -framework SystemConfiguration";` after each target's `PRODUCT_BUNDLE_IDENTIFIER`, grep-guarded for idempotency. Rationale: `hickory-resolver` (system DNS config) and `reqwest` (proxy detection) pull in the `system-configuration` crate, which needs Apple's `SystemConfiguration.framework`. On host builds rustc honors the crate's `#[link(kind="framework")]`, but the iOS staticlib is linked by Xcode, which never sees that directive — so without this the build fails at `Ld` with `Undefined symbols ... _SC*`.
- `apps/identity-wallet/scripts/ios-check.sh` — now also greps the pbxproj for `SystemConfiguration` and fails if missing.
- `justfile` — the `ios-dev` recipe now takes an optional device arg: `just ios-dev "iPhone 17 Pro Max"` forces a specific simulator; no arg = `cargo tauri ios dev` auto-detect (which PREFERS a connected physical device, requiring code signing).
- `apps/identity-wallet/src-tauri/tauri.conf.json` — gained `bundle.iOS.frameworks: ["SystemConfiguration"]`. Note in the docs that this is best-effort declarative only: `cargo tauri ios init` preserves an existing `project.yml` (it does NOT regenerate it), so this config only seeds a FRESH `project.yml` and does not retroactively apply — the `ios-postinit` Patch E is the enforced mechanism.
