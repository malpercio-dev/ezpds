# Working with Devenv

## Overview

**devenv** manages project dependencies through Nix. Commands like `pnpm`, `node`, `turbo` live in `.devenv/profile/bin/` and are only available inside a devenv shell.

**Core principle:** Verify you're in devenv before running managed commands. Never manually modify PATH.

## Quick Reference

| Task | Command | When |
|------|---------|------|
| Check if in devenv | `echo $DEVENV_STATE` | Shows path if active, empty if not |
| Enter interactive shell | `devenv shell` | For multiple commands, development work |
| Run single command | `devenv shell -c "command"` | One-off execution, CI scripts |
| Auto-activate (best) | `direnv allow` (once) | Automatic activation on `cd` |
| Exit devenv shell | `exit` | Leave interactive shell |

## Patterns

### Interactive Development

```bash
devenv shell      # Enter shell once
pnpm install      # Run multiple commands
pnpm build
pnpm test
exit              # Leave when done
```

### One-Off Commands

```bash
devenv shell -c "pnpm build"                        # Single command
devenv shell -c "pnpm install && pnpm build"        # Chain commands
```

### Scripts and Automation

```bash
#!/usr/bin/env bash
set -e

# Auto-activate devenv if not already in it
if [ -z "$DEVENV_STATE" ]; then
  exec devenv shell -c " $@"
fi

# Rest of script runs with devenv active
pnpm install && pnpm build && pnpm test
```

**Why `exec`:** Replaces current process instead of nesting shells.

### Automatic Activation with direnv (Best Practice)

**Setup once:**
```bash
brew install direnv                           # Install direnv
echo 'eval "$(direnv hook zsh)"' >> ~/.zshrc  # Hook into shell (or bash)
source ~/.zshrc                               # Reload config
cd /path/to/project                           # Navigate to project
direnv allow                                  # Allow activation
```

**Then just use commands:**
```bash
cd /path/to/project   # Automatically activates devenv
pnpm build            # Commands work immediately
```

**Advantages:** No manual `devenv shell`, auto-activates/deactivates on `cd`, team consistency.

**Note:** If project has `.envrc` file, it's already configured for direnv.

## Common Mistakes

### ❌ Manual PATH Modification

```bash
# DON'T
export PATH=.devenv/profile/bin:$PATH
PATH=.devenv/profile/bin:$PATH pnpm build
```

**Why wrong:** `.devenv/profile/bin/` paths change on updates, bypasses environment setup, breaks if devenv not built.

**Do instead:** `devenv shell -c "pnpm build"` or use direnv.

### ❌ Global Package Installation

```bash
# DON'T
npm install -g turbo
pnpm add -g some-package
```

**Why wrong:** devenv manages dependencies via Nix. Global installs create version conflicts, not reproducible.

**Do instead:** Check if in devenv first, or add to `devenv.nix`.

### ❌ Nested Shells

```bash
# DON'T enter devenv when already in devenv
devenv shell  # Creates nested shell
```

**Why wrong:** Wastes resources, confusing exit behavior.

**Do instead:** Check `$DEVENV_STATE` first: `[ -n "$DEVENV_STATE" ] && echo "Already in devenv"`

### ❌ Assuming Commands Are Available

```bash
# DON'T run without checking environment
pnpm build  # Might work, might not
```

**Why wrong:** Inconsistent behavior, fails for others/CI.

**Do instead:** Use `devenv shell -c` or verify `$DEVENV_STATE` first.

## Troubleshooting

**Command not found after entering devenv:**
- Run `devenv update` to rebuild environment
- Verify `.devenv/` directory exists

**Nested shell confusion:**
- Check depth: `echo $SHLVL`
- Exit to fresh shell: `exec bash`

**PATH seems wrong:**
- Never modify PATH manually - let devenv manage it
- Rebuild: `devenv update`

## When NOT to Use

- Already in devenv (check `$DEVENV_STATE` first)
- System commands (`ls`, `grep`, `git` don't need devenv)
- Other project's commands (only use for current project)
