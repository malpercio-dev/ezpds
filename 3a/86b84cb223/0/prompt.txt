### Task 2: `get_records_since_rev` selection logic

**Implementation:**
- **`get_records_since_rev(state, did, header_rev) -&gt; LocalRecords`** — Imperative Shell function that:
  1. Returns empty when `header_rev` is None (AC5.3: missing header)
  2. Fetches recent commits for the DID via `recent_commits_for_did` (200-record limit)
  3. Decodes each commit event using `crate::firehose::decode_stored_event`
  4. Walks newest-first, stopping at `rev &lt;= header_rev` (string TID comparison)
  5. Collects distinct `(collection, rkey)` touched, keeping the newest event time
  6. Opens the repo once via `Repository::open(SqliteBlockStore, root_cid)`
  7. Reads current values for each touched record using `repo_engine::get_record_json`
  8. Skips deleted records (returns None) — AC5.2
  9. Buckets records into `profile` (app.bsky.actor.profile/self) and `posts` (app.bsky.feed.post) — AC5.1
  10. Returns correctly bucketed `LocalRecords` with accurate count

- **`local_lag_ms(local: &amp;LocalRecords) -&gt; Option&lt;i64&gt;`** — Helper that:
  1. Returns None when no records are present
  2. Parses RFC 3339 `indexed_at` timestamps and finds the oldest
  3. Computes milliseconds since the oldest record's `indexed_at`
  4. Returns lag for AC4.3 compliance

**Key Design Decisions:**
- Opens repo **once** and reuses across all record reads (efficiency)
- Uses best-effort error handling — skips individual records on per-key errors, never fails the entire operation
- Directly uses `CommitEvent.time` (RFC 3339) as `indexed_at` (matches firehose emission timestamp)
- Uses `.entry()` API for HashMap to avoid clippy `map_entry` warnings
